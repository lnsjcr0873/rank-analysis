1. 17 分制评分（Akari 算法）与 WeGame 综合评分双口径混乱
关联文件:

src-tauri/src/lcu/api/match_history.rs（wegame_score 10 分制）

问题分析:
项目中存在两套完全不同的评分算法同时运行且口径打架：
score.rs：17 分制，满分 17，包含 linear() 线性映射加权，输出在 MatchDetailScoreTab.vue 中展示。
match_history.rs 和 useMatchDetailPlayers.ts：10 分制 WeGame 式综合评分，直接决定 MVP 和 SVP 的计算。

四、 SGP 跨区网络通信协议隐患
1. 跨区 SGP 凭证失效与空转
关联文件: src-tauri/src/lcu/api/sgp.rs
问题分析:
get_entitlements_access_token 缓存时间为 Duration::from_secs(30)，而 get_league_session_token 缓存时间为 Duration::from_secs(60)。
SGP 跨区查询使用 SGP_SUMMARY_CACHE，且遇到 404 会将结果放入 SGP_RANKED_NEGATIVE（缓存负向结果 5 分钟）。
漏洞: 当玩家刚刚完成一场跨区段位晋级赛或者账号首次在某大区创建角色时，若首次查询遭遇瞬时 404（例如新角色在网关上同步有数秒延迟），该大区被立即封锁 5 分钟的负缓存。在这 5 分钟内，即使玩家刷新页面，后端也会强行返回默认空段位（SgpRankedStats::default()），造成数据长达 5 分钟的假死。
修复方案:
负向缓存（Negative Cache）的时间必须大幅缩短（建议从 5 分钟缩减为 10~15 秒），或者提供前端“强制刷新”参数绕过负向缓存。

关联文件: src-tauri/src/lcu/api/sgp.rs

关联文件:

问题根因:
在 config.rs 中，Value 枚举声明如下：
code
Rust
#[derive(Serialize, Deserialize, Debug, Clone, PartialEq)]
pub enum Value {
    Null,
    String(String),
    Integer(i64),
    Float(f64),
    Boolean(bool),
    List(Vec<Value>),
    Map(HashMap<String, Value>),
}
该枚举没有配置 #[serde(untagged)]，因此 serde 在将其序列化为 JSON 时采用的是**外部标签（Externally Tagged）**格式：

    "type": "rank-analysis-backup",
    "exportedAt": now_unix() * 1000,
    "playerNotes": notes_val, // <--- 这里的 notes_val 是带 {"Map": ...} 的枚举！
    "appConfig": config::config_snapshot(false).await,
});
导出的备份文件中，playerNotes 变成了：
code
JSON
"playerNotes": {
  "Map": {
    "<puuid>": {
      "Map": {
        "note": { "String": "备注" },
        "label": { "String": "friendly" }
      }
    }
  }
}
破坏性后果:
当用户使用「从文件导入」恢复备份时，前端 DataSync.vue 将其送入 notesStore.importNotes(parsed.playerNotes)。前端的校验函数 isValidNote(v) 预期字段为 typeof v.note === 'string'，遇到 { "String": "备注" } 判定全部为损坏条目（invalid）。

在 build_backup_json() 中必须使用 config_value_to_json 将 config::Value 转换为标准的 JSON 扁平对象再写入，或者给 config::Value 加上 #[serde(untagged)]。

code

function polyPoints(values: number[]): string {
  const max = Math.max(1, ...values)
  const step = values.length > 1 ? (CURVE_W - PAD * 2) / (values.length - 1) : CURVE_W - PAD * 2
  return values
    .map(

2. Wilson Score 区间下限公式中样本数量为 0 的边界值溢出
文件: src-tauri/src/mayhem/db.rs (wilson_score_lower)
代码片段:
code
Rust
pub fn wilson_score_lower(wins: i64, total: i64) -> f64 {
    if total <= 0 {
        return 0.0;
    }
    let n = total as f64;
    let p = wins as f64 / n;
    let z = 1.96; // 95% 置信度
    let z2 = z * z;
    let numerator = p + (z2 / (2.0 * n)) - z * ((p * (1.0 - p) / n + z2 / (4.0 * n * n)).max(0.0).sqrt());
    let denominator = 1.0 + z2 / n;
    (numerator / denominator).clamp(0.0, 1.0)
}
隐患:
当数据库因异常写入存在 wins > total 的脏记录（如并发写入或不同模式场次统计重叠时），p > 1.0，导致 p * (1.0 - p) 变成负数。虽然有 .max(0.0) 防护开了根号，但计算出的分子 numerator 会严重失真，产生低于正常胜率的荒谬分值，并被记录进海克斯全局胜率库，污染客户端的强化推荐排序。

序号	漏洞类型	触发场景	影响后果
1	时区逻辑 Bug	本地机器处于非 UTC 时区（如北京时间 UTC+8）	赛后决策对账时间戳错位 8 小时，回测功能 100% 报错失效
2	死锁/闪退	用户在“关于”页面点击“以管理员身份重启”	新老进程争夺 SQLite / 配置文件独占锁，新应用直接闪退
3	自动化失控	规则配置中添加了“不包含”但未选择具体英雄	规则无条件永久触发，霸占所有选人决策并秒选/秒 Ban
4	内存暴涨 (OOM)	用户使用“全量收集”拉取上百局完整战绩时	完整事件流对象挤满响应式内存树，触发 Webview 内存溢出白屏崩溃
