问题代码（save_collected_games_in 函数）：
code
Rust
let mut stmt = tx.prepare_cached(
    "INSERT INTO collected_games_v2 (region, name, game_id, json, updated_at)
     VALUES (?1, ?2, ?3, ?4, ?5)
     ON CONFLICT(region, name, game_id) DO UPDATE SET
     json=excluded.json, updated_at=excluded.updated_at",

    let json = serde_json::to_string(g).map_err(serde_to_sqlite_err)?;

原因分析：SQL 语句中声明了 ?1, ?2, ?3, ?4, ?5 五个占位符，且表字段包含 updated_at TEXT NOT NULL，但循环执行时只传入了 4 个参数（updated_at 变量被传入函数后未被传入 params!）。这会导致 rusqlite::Error::InvalidParameterCount(4, 5)，造成跨区及已收集对局持久化每次调用必崩/必报事务回滚。

问题代码（handle_event 函数）：
code
Rust
async fn handle_event(&self, event: &Value, debounce_tx: &tokio::sync::mpsc::Sender<String>) {
    if let Some(uri) = event.get("uri").and_then(|v| v.as_str()) {
        let data = event.get("data");
        if let Some(phase) = data.and_then(|d| d.as_str()) {
            // ❌ 没有校验 uri 是否为 /lol-gameflow/v1/gameflow-phase！
            crate::lcu::api::phase::update_phase_cache(phase.to_string());
        }
        let _ = debounce_tx.try_send(uri.to_string());
    }
}
原因分析：LCU WebSocket 会广播大量 WAMP 事件。只要任意事件的 data 是一个 JSON 字符串（例如召唤师状态信息、聊天通道名、通知提示文本等），都会执行 update_phase_cache，将缓存的游戏阶段覆写为该无关文本。这会导致 get_phase() 返回错误状态，使自动接受匹配、自动 BP、浮窗弹出等依赖 Phase 的核心功能完全紊乱。
修复方案：校验 URI 是否确实是 Gameflow 阶段接口：
code
Rust
if uri == "/lol-gameflow/v1/gameflow-phase" {
    if let Some(phase) = data.and_then(|d| d.as_str()) {
        crate::lcu::api::phase::update_phase_cache(phase.to_string());
    }
}
3. automation.rs & champion_select.rs：选人会话 1 秒缓存导致自动 BP 产生自发性误判接管（False Override）【已完成：bug 真实存在。修复：新增 invalidate_select_session_cache，patch_session_action/swap_bench_champion/accept_trade/decline_trade 成功后失效缓存（spells 不在会话结构内，跳过）。GNU check/clippy/fmt 全过】
文件路径：
rank-analysis-app/src-tauri/src/lcu/api/champion_select.rs
rank-analysis-app/src-tauri/src/automation.rs
原因分析：
get_champion_select_session() 内部维护了一个 1 秒的内存缓存（SELECT_CACHE）。
自动选人逻辑执行 patch_session_action 预选英雄 X 后，调用 store::set_last_hovered(Some(X))。
但 patch_session_action 之后并没有使 SELECT_CACHE 失效。
随后在 start_bp_decision_automation 中调用 get_champion_select_session() 时，因为时间未过 1 秒，读到的是上一次本地或 LCU 旧的 champion_id（例如 Y）。
detect_override 检测到 current_hover(Y) != 0 && current_hover(Y) != our_hover(X)，判定为「用户手动干预接管」（User Overridden），并调用 store::mark_overridden(action_id)。
一旦被标记为 overridden，后续哪怕时间到了，程序也直接跳过，导致整局选人自动锁定被彻底放弃。
修复方案：在 patch_session_action 和 swap_bench_champion 成功后，立即清理或重置 SELECT_CACHE；或者在 detect_override 中增加短期防抖容忍，等待 LCU 实际回执。

pub(crate) fn parse_position(s: &str) -> Option<Position> {
    match s.to_ascii_lowercase().as_str() {

但是绑定到 <n-select v-model:value="selectPickChampionId"> 的变量没有被置回 null。
下拉框一直停留在刚刚选中的英雄名称上，无法恢复为「添加英雄」的 Placeholder 提示；用户若想再次选择同一个英雄进行配置调整时，无法触发 update:value 事件。
修复方案：在 addPickData 和 addBanData 尾部加上 selectPickChampionId.value = null 与 selectBanChampionId.value = null。

三、 LCU 通信与架构隐患 (Architecture & Stability)
7. lcu_get_raw 启动首秒认证锁死：时间戳初始化导致突发 401 无法重试
文件路径：rank-analysis-app/src-tauri/src/lcu/util/http.rs
原因分析：
code
Rust
let last_refresh = LAST_REFRESH_TIME.get_or_init(|| Mutex::new(Instant::now()));
// ...
if now.duration_since(*last_refresh_guard) < Duration::from_secs(1) {
    // ❌ 距离上次刷新不足 1 秒，直接返回旧的 AUTH！
    let auth = AUTH.get().expect("AUTH not initialized");
    return Ok(auth_guard.clone());
}
LAST_REFRESH_TIME 在进程启动时被直接初始化为 Instant::now()。
这意味着：在程序启动后的最初 1 秒内，refresh_auth 会认为「刚刚才刷新过」。
如果应用在启动瞬间遇到 LCU 令牌变更或重连，首次请求触发 401 并尝试 refresh_auth()，由于命中了 1 秒冷却，它直接返回了失效的旧凭据，导致重试依旧 401 并彻底抛错，白白错失自愈机会。
修复方案：将初始时间初始化为一个较早的时刻，例如 Instant::now() - Duration::from_secs(10)，允许启动初期的自愈重试立即生效。
8. cloud_push_notes：Tombstone（墓碑记录）导致超过 5MB 限制的用户永远无法清理空间
文件路径：
rank-analysis-app/src-tauri/src/command/cloud_sync.rs
rank-analysis-app/src/features/settings/stores/playerNotes.ts
原因分析：
后端在 push_payload 中设置了防御：if payload_bytes.len() > MAX_PUSH_BYTES { return Err("本地备注过大（>5MB），已拒绝推送，请先清理备注"); }。
前端在 playerNotes.ts 中删除备注时，为了支持跨设备同步的 CRDT 最终一致性，采用的是打墓碑标记（deleted: true，TTL 30天），并不会立刻在 JSON 中将该 key 物理移除。
后果：一旦某个用户通过频繁添加/导入导致备注超过 5MB 限制被云端拦截，即便他在前端界面上点击删除所有备注，本地 JSON 的体积反而因为追加了 deleted: true 变大，无法缩减回 5MB 以内。这会导致该账号的云同步永久死锁，除非等待 30 天墓碑过期或手动清空本地配置文件。
修复方案：在推送云端前，如果检测到超限，可提供「立即物理清理（彻底清除已标记删除的记录）」操作，或对 encounters 历史遇见大数组进行智能裁剪后再推送。
